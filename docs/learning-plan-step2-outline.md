# テストエンジニア育成講座 Step2（応用編） 学習プラン（v0.1）

## 対象と目的

- **対象**: Step1（基礎編・全3回）を修了したメンバー
- **ゴール**: 「仕様把握→設計→実行管理→報告を一人で回せる」から、**テスト戦略を自分で選び、上流とAIに品質活動を広げ、チームの品質を牽引できる人材**へ
- **対象ドメイン**: Step1と同じく業務システム（例題は経費精算システムで統一）
- **方針**:
  - Step1と同様、考え方・マインドセット重視。ツールの操作方法ではなく「判断軸」を教える
  - 中級QAの成長軸としてリサーチで共通して挙がった **①テスト戦略・リスク分析 ②シフトレフト（上流への関与） ③自動化とAI活用** に1回ずつ対応させる
  - ISTQB Advanced Level（Test Analyst / Test Manager）および CT-AI / CT-GenAI の入口を薄くカバーする位置づけ（シラバス対応は各回末尾に小さく記載）
  - 毎回ワークを入れる

### 第4回 テスト戦略とリスクベースドテスト（90分）

Step1第2回で触れた「リスクの濃淡」を本格化。テスト計画の一段上にある「戦略」を自分で選べるようになる回。

| 時間 | 内容 |
|---|---|
| 5分 | Step1の振り返りとStep2のゴール |
| 15分 | テスト戦略とアプローチ: 分析的・モデルベース・経験ベースなどアプローチの種類、プロジェクト特性に応じた選択・組み合わせ |
| 15分 | リスクベースドテスト — 評価のものさし: 影響度・発生確率の判断軸、リスクマトリクス、リスクレベル→テストの濃淡への翻訳 |
| 15分 | **リスクはどう洗い出すか**: 出す作業と評価する作業を分ける原則、4つのレンズ（データの流れ／変更点／品質特性／過去と現場）、引き金の質問リスト、リスク文の型（どこで・何が起きて・どう困るか）、粒度の整え方。非機能リスクは「品質特性のレンズ」として組み込み |
| 25分 | **ワーク①（2ステップ）**: Step A リスクの洗い出し（個人3分→グループ7分→共有3分、目標15個）／ Step B 評価と濃淡（グループ9分→共有3分、6件を選んでマトリクス配置） |
| 10分 | 探索的テスト入門: スクリプトテストとの補完関係、セッションベースドテスト（SBTM）、チャーターの書き方（講義のみ。チャーター作成はOJTへの持ち帰り） |
| 5分 | まとめ |

### 第5回 シフトレフトと上流品質（90分）

「テストフェーズで頑張る人」から「要件・設計段階から品質に関与する人」へ。QAの役割が「品質の番人」から「品質のアクセラレーター」に変わる業界トレンドに直結する回。Step1第2回の「質問力」の発展形。

| 時間 | 内容 |
|---|---|
| 5分 | 前回の振り返り |
| 23分 | シフトレフトの費用対効果: **「並走」の中身**（静的テスト＝ドキュメントもテスト対象／①読む・②作るの2本立て／並走している・していないQAの対比）、欠陥の発見が遅いほど修正コストが跳ね上がる、**もう一つの転換＝検出から予防へ**（QC/QA。シフトレフト＝時間軸とは別の軸であることを明示）→「品質の番人から品質のアクセラレーターへ」 |
| 15分 | レビュー技法: 観点を持った要件・設計レビュー、指摘の伝え方（人ではなく成果物へ） |
| 15分 | **ワーク①**: 経費精算の要件定義書ドラフトをレビューし、テスト実行前に欠陥を検出する |
| 15分 | 受け入れ条件と実例マッピング: 仕様の認識合わせを具体例で行う、ATDDの考え方 |
| 15分 | **ワーク②**: ユーザーストーリー+受け入れ条件から実例マッピングで具体例を洗い出す |
| 7分 | アジャイル開発でのQAの動き方・まとめ |

※ 2節を厚くしたぶん合計95分。90分厳守なら3節または7節から5分を回収する（未調整）

### 第6回 テスト自動化とAI時代のQA（90分）

自動化ツールの操作ではなく「何を・なぜ自動化するか」の判断軸を扱い、**AI活用の現在地**と**QAと開発の関わり方（インプロセスQA）**を厚めに扱う回。「QAの仕事はなくならないが、実行者から監督者・設計者に変わる」という一貫したストーリーで構成し、キャリアの地図を渡して講座全体を閉じる。

| 時間 | 内容 |
|---|---|
| 5分 | 前回の振り返り |
| 15分 | テスト自動化の判断軸: テストピラミッド、ROI、自動化すべきもの/すべきでないもの |
| 20分 | **AI×QAの現在地マップ**: 5類型（①テストケース生成 ②E2EツールのAI機能 ③自律探索エージェント ④レビュー・起票支援 ⑤LLMプロダクトの評価）×「できること・できないこと」を企業事例の実数付きで。失敗談（AIに直接実行させるとFlaky化・偽陽性、runner/judge分離の必要性）から「たたき台はAI、検証は人間」の原則を導く。※AI生成テストケースのレビュー演習は任意ミニ演習（自習用）としてページ内に収録 |
| 15分 | **QAの仕事はどう変わるか**: 縮む業務（定型実行・ケース作成）/残る業務（リスク判断・優先順位・探索）/新領域（QA4AI）。「LLMでも半分はいつものテスト」で基礎の価値を確認し、「守るQA→創るQA」で締める |
| 10分 | **ワーク**: ディスカッション「AIに任せたい仕事・自分が握り続けたい仕事」を各自書き出して共有（AIパートの締め。「握り続けたい仕事をどこで発揮するか」を次セクションへの布石にする） |
| 15分 | **QAと開発の関わり方 — インプロセスQA**: アウトプロセス型（検証プロセスに閉じたQA）の構造的限界、開発チームに参加して伴走するインプロセスQA、テスト以外の品質担保（観点提供・仕様レビュー・開発者テストのレビュー・ペアテスト＝Quality Assistance/QA Enabling）、信頼を成果の先払いで作る「明日からの一歩」4段階 |
| 10分 | キャリアの地図とこれからの学び方: アナリスト/マネージャー/自動化・QEの3方向、JSTQB AL・CT-AI/CT-GenAI、JaSST・SpeakerDeckの追い方 — 講座全体のクロージング |

## 更新履歴

- 2026-07-31: 第5回セクション2の後半を「もう一つのシフトレフト — 原因のほうへずらす」→**「もう一つの転換 — 検出から予防へ」**に再修正。理由: ISTQBのシフトレフトの定義は時間軸（活動をより早い工程へ）に限られ、因果をさかのぼるQC→QAをシフトレフトと呼ぶのは定義から外れるため。(1) 「シフトレフトと呼ぶ」という断定を削除し、時間・工程軸＝シフトレフト／因果・対象軸＝QC→QA という用語整理表を追加、(2) 2軸が独立であることを示す例表（単体テスト高速化＝シフトレフトだがQC寄り／リリース後の欠陥分析でプロセス改善＝QAだが時期は遅い／過去の欠陥分析を次回の要件レビュー観点に組み込む＝両方）を追加、(3) 「その種類の欠陥が二度と生まれなくなる」→「同種の欠陥の発生頻度を下げる」に修正（ISTQBも完全防止は断定していない）、(4) 「締め日・月末が漏れやすい」は傾向であって根本原因ではない点と、観点リスト追加は根本原因ではなく**予防処置**である点を補足ボックスで明示。ゴール・持ち帰り・シラバス対応も更新。2節を21→23分（合計95分、要調整）

- 2026-07-31: 第5回セクション2「シフトレフト — テストを左（上流）へずらす」の説明を厚くした。「並走」が抽象的だったため、(1) 静的テスト＝要件書・設計書もテスト対象なので工程ごとに始められる仕事がある、(2) 並走中のQA活動は「①読む（レビュー）／②作る（テスト設計の前倒し）」の2本立て、②は書けない箇所＝仕様の穴の発見になるので②自体が①になる、(3) 基本設計フェーズ2週間の「並走していない／している」対比表、(4) 「シフトレフト＝テスト実行の前倒しではない」という誤解ボックス、を追加。2節を18→21分（合計93分、要調整）

- 2026-07-31: 第4回を再構成。背景: ワーク①が「リスクの洗い出し」と「マトリクス評価」を同時にやらせる作りで受講者が追いつけない懸念、かつ洗い出し方の解説が薄かったため。(1) 新セクション「4. リスクはどう洗い出すか」（15分）を追加（4つのレンズ・引き金の質問・リスク文の型・粒度）、(2) ワーク①をStep A（洗い出し）／Step B（評価と濃淡）の2段階＋各共有に分割し15→25分、(3) **ワーク②ミニ探索セッションを講義枠から削除**（教材は探索セクション内の任意/OJT用detailsとして残置）、(4) 非機能リスクの3点セットはセクション3から「品質特性のレンズ」へ移動、(5) 探索的テスト入門15→10分・リスクベースドテスト20→15分。合計90分維持

- 2026-07-31: 第5回セクション2の当該小見出しを「もう一つのシフトレフト — 原因のほうへずらす」に改題。QAとQCの定義の違いを説明する構成をやめ、「シフトレフトには時間軸（早く見つける）と原因（根本原因に手を入れて、その種類の欠陥を生ませない）の2方向がある」という主張に軌道修正。対比表も「同じ欠陥に対して右端/左端のどちらに手を入れるか」（触る対象・効果の範囲・テスト結果の使い道・具体例）に組み替え。今日のゴールと持ち帰りの該当項目も同じ言い方に統一

- 2026-07-30: 第5回セクション2に「テストとQAは同じではない」（QC=製品志向・是正的／QA=プロセス志向・予防的の対比表）を追加。第1回で追加した「根本原因→エラー→欠陥→故障」の連鎖を橋にして、「右側を捕まえるのがテスト、左端に手を入れるのがQA」＝Step1がQC・Step2がQA、という講座構成の説明に接続。時間は2節を15→18分、7節を10→7分にして90分維持
